# خطة نقل mosque-media لـ Next.js + TypeScript + Tailwind + shadcn/ui

> **الحالة (24 نوفمبر 2026):** المراحل 0 لـ 6 خلصت على فرع `v2`. المرحلة 7 (الإطلاق) مستنية موافقتك. المرحلة 8 (نقل موقع الحسني) لسه متبدأتش.
>
> **اللي اتغير عن الخطة وقت التنفيذ:**
> - **ميزانية السرعة:** كتبت 110KB، وطلعت غلط مني، لأن React وNext.js لوحدهم حوالي 116KB. الحد بقى 200KB، والقياس الفعلي **178KB**.
> - **PWA:** اتعمل بـ Service Worker مكتوب بإيدينا بدل Serwist، لأن Serwist مش متوافق مع Turbopack.
> - **قواعد البيانات:** جدول مستندات JSON بسيط وجدول تاريخ، من غير Drizzle. Postgres (وبالتالي Supabase وNeon) وSQLite/Turso بيشتغلوا بنفس الكود.
> - **الصوت:** S3/R2 اتعمل. Vercel Blob بقى للرفع من الداشبورد بس، مش مكان دايم للصوت.
> موقع الحسني الحالي (`alhasany-site`) **مش هيتلمس** لحد ما النسخة الجديدة تثبت إنها أحسن منه أو زيه بالظبط.

## الخلاصة في سطور

- **هنبني من جديد** واجهة mosque-media على Next.js، لكن **نفس الفكرة ونفس البيانات**: الموقع على Vercel، والصوت على GitHub Releases، والبيانات في `lessons.json` و`overrides.json`، والداشبورد على `/lawha`، وتطبيق PWA عربي من اليمين للشمال.
- **أدوات Python تفضل Python** (الاستيراد، البناء، رفع الصوت، والأدوات الجاية زي تقطيع الصوت والتفريغ النصي). الموقع بس بيقرا اللي بتطلّعه.
- **الصفحات هتتبني جاهزة وقت النشر** (Static Generation)، فتفضل سريعة زي دلوقتي. وفوقها هنكسب إن كل درس هيبقى ليه صفحة حقيقية بعنوانها وصورتها لما تتشارك على واتساب أو تتلاقى على جوجل.
- **البيانات موديول:** المسجد يختار يخزّن فين (ملفات JSON مجانًا زي دلوقتي، أو Supabase، أو Postgres…)، والصوت كمان (GitHub، أو R2، أو Vercel Blob). الكود واحد.
- **لغات كتير من أول يوم:** عربي وإنجليزي في الأول، وبعدهم أردو وهندي وروسي، وأي لغة تانية = ملف ترجمة.
- **8 مراحل.** في آخر كل مرحلة هتشوف لينك تجربة على Vercel (مش الموقع الحقيقي) وتوافق قبل اللي بعدها.

## 2. شكل الفولدرات

**اقتراحي: مستودع واحد بسيط، مش monorepo دلوقتي.** الـ monorepo (أكتر من مشروع JavaScript في مستودع واحد) بيزوّد التعقيد على أي حد هيستخدم المشروع، ومفيش حاجة محتاجاه النهارده. لو بعدين عملنا مثلًا تطبيق سطح مكتب لأداة التقطيع، ننقل وقتها، والنقلة سهلة.

```
mosque-media/
├─ app/                     ← صفحات الموقع (Next.js)
│  ├─ (site)/               ← الصفحات العامة
│  │  ├─ page.tsx           ← الرئيسية
│  │  ├─ s/[slug]/[[...tab]]/page.tsx   ← صفحة الشيخ وسلاسله
│  │  ├─ l/[id]/page.tsx    ← صفحة الدرس
│  │  ├─ c/[key]/page.tsx   ← المجموعات (رمضان)
│  │  ├─ all/ lessons/ khutab/ tilawat/ series/ weekly/ latest/ popular/ others/ search/
│  ├─ lawha/                ← الداشبورد
│  ├─ api/                  ← dl / admin / channel
│  ├─ layout.tsx            ← الهيدر + المشغّل (بيفضل شغال وانت بتتنقل بين الصفحات)
│  └─ manifest.ts, icon.tsx ← بيانات التطبيق والأيقونات (بتتعمل من الإعدادات)
├─ components/              ← مكونات الموقع (ui/ = مكونات shadcn)
├─ lib/                     ← تطبيق overrides، البحث، التاريخ الهجري
│  └─ storage/              ← واجهة البيانات + الأدابترات (github-json, supabase, postgres, s3 …)
├─ messages/                ← ملفات الترجمة: ar.json, en.json, ur.json, hi.json, ru.json …
├─ content/                 ← lessons.json + overrides.json (Python و الداشبورد بيكتبوهم)
├─ site.config.json         ← نفس الملف، ونفس الخانات
├─ assets/                  ← لوجو المسجد
├─ tools/                   ← أدوات Python (زي ما هي)
├─ data/                    ← بيانات Python (messages / series / audio …)
├─ docs/ AGENTS.md README.md
└─ tests/                   ← اختبارات Playwright (بتتأكد إن الصفحات شغالة)
```

## 3. الألوان والهوية (site.config.json ← Tailwind/shadcn)

نفس خانات الإعدادات الحالية، بس بتتحول لمتغيرات CSS بيستخدمها shadcn:

| في site.config.json | في الموقع |
|---|---|
| `colors.primary` | `--primary` (الزراير والعناوين) و`--ring` |
| `colors.highlight` | `--accent` (زرار «استمع» وشريط التقدم) |
| `colors.background` | `--background` (الوضع الليلي ليه ألوانه الثابتة المحايدة) |
| `colors.tones[]` | `--tone-1`, `--tone-2` … (أغلفة المشايخ) |
| `design.corners` | `--radius` (حادة 4px / ناعمة 12px / مدوّرة 22px) |
| `design.font` | الخط بيتحمّل بـ `next/font` من القايمة المسموحة (8 خطوط)، ومن غير ما الصفحة "تنط" وهي بتحمل |
| `design.header` | فاتح / بلون المسجد |
| `assets/logo.*` | الأيقونات وصورة المشاركة بتتعمل **وقت البناء** من غير Pillow |

- **مفيش ملفات بتتولد بإيدك تاني** (زي `theme.css` و`site.js` و`index.html`). الموقع بيقرا الإعدادات وهو بيتبني.
- **حماية هويتك تفضل:** فحص zod بيرفض ألوان الحسني وخطوطه قبل البناء.
- **اللي عايز يغيّر الشكل أكتر** يعدّل مكونات `components/` براحته. shadcn بيحط الكود عنده مش في مكتبة مقفولة.

| الحالي | الجديد |
|---|---|
| `api/dl.js` | `app/api/dl/route.ts`: نفس الشغل (التحميل باسم الدرس بالعربي) |
| `api/channel.js` | `app/api/channel/route.ts`: آخر رسايل القناة للداشبورد |
| `api/admin.js` (بيدّي مفتاح GitHub للمتصفح) | **تحسين أمان:** الدخول بيعمل جلسة (cookie آمنة)، و**المفتاح عمره ما بيخرج من السيرفر**. التعديلات بتتحفظ عن طريق `app/api/admin/save/route.ts` |
| `/lawha` (JavaScript عادي) | صفحة بمكونات shadcn: جداول، نوافذ تعديل، بحث، تبويبات. نفس الوظايف بالظبط |

**رفع ملفات الصوت من الداشبورد: ✅ اتقرر Vercel Blob.**
Vercel مش بيسمح إن ملف أكبر من 4.5 ميجا يعدّي من السيرفر، والخطب بتبقى 20 لـ 40 ميجا. عندنا اختيارين:

1. **(ده اللي اتقرر)** الملف يترفع مباشرة من المتصفح على **Vercel Blob** (مجاني لحد حجم معين) بإذن مؤقت من السيرفر. بعدها GitHub Actions ينقله لـ Releases ويمسحه من Blob. كده المفتاح ميخرجش أبدًا.
2. نسيبه زي دلوقتي: المتصفح بياخد مفتاح GitHub وقت الجلسة بس ويرفع بيه. أبسط، بس أقل أمانًا.

## 6. ميزانية السرعة

قياس الموقع الحالي النهارده (بعد الضغط): الصفحة 2.7KB + الكود 18.8KB + التصميم 14.6KB + البيانات 14.6KB ≈ **51KB** لأول فتحة.

| المقياس | الحد المسموح |
|---|---|
| JavaScript لأول فتحة في الصفحات العامة | **≤ 200KB مضغوط** (React وNext.js لوحدهم ~116KB). **المقاس: 178KB** |
| حجم بيانات أي صفحة | ≤ 25KB مضغوط (كل صفحة بتاخد بياناتها بس، مش الـ 416 مقطع) |
| ظهور المحتوى (LCP) على موبايل متوسط بنت 4G | **< 1.5 ثانية** |
| ثبات الصفحة وهي بتحمل (CLS) | < 0.05 |
| Lighthouse (السرعة والوصول وSEO) | ≥ 95 |

- فهرس البحث (~15KB) بيتحمّل **بس** لما حد يفتح البحث.
- المشغّل والفلاتر هما بس اللي بيشتغلوا في المتصفح، والباقي صفحات جاهزة.
- **فيه اختبار تلقائي** بيفشّل البناء لو الحجم عدّى الحدود دي.

> الأمانة: Next.js أتقل من الموقع الحالي في أول فتحة (178KB مقابل ~51KB). بس الصفحات بتظهر أسرع، لأن المحتوى جاي جاهز في الـ HTML من غير ما يستنى الكود، والتنقل بين الصفحات بعد كده فوري. المشغّل والقايمة الجانبية بيتحملوا بس لما حد يستخدمهم.

## 8. البيانات كموديول (كل مسجد يختار يخزّن فين)

بدل ما الموقع يبقى مربوط بطريقة تخزين واحدة، هيبقى فيه **واجهة ثابتة** (interface)، وتحتها **أدابترات** (adapters) قابلة للتبديل. المسجد بيختار من `site.config.json`، والكود نفسه مش بيتغير:

```json
"storage": {
  "data":  { "provider": "github-json" },
  "audio": { "provider": "github-releases" }
}
```

**البيانات (المقاطع، المشايخ، السلاسل، تعديلات الداشبورد):**

| الأدابتر | مناسب لمين | التكلفة |
|---|---|---|
| `github-json` **(الافتراضي)** | زي دلوقتي بالظبط: ملفات JSON في المستودع، ومفيش أي حساب زيادة | مجاني |
| `supabase` | اللي عايز قاعدة بيانات حقيقية ولوحة جداول | مجاني لحد حجم معين |
| `postgres` | أي Postgres (Neon، Vercel Postgres، سيرفر المسجد نفسه) | حسب المزوّد |
| `sqlite` (Turso) | خفيف وسريع | مجاني لحد حجم معين |

**الصوت:**

| الأدابتر | ملاحظة |
|---|---|
| `github-releases` **(الافتراضي)** | زي دلوقتي |
| `s3` (Cloudflare R2، Backblaze، AWS…) | للمساجد اللي عندها صوت كتير جدًا. R2 مفيش عليه رسوم تحميل |
| `vercel-blob` | أبسط حاجة لو عايز كله على Vercel |

**إزاي بيشتغل:**
- كل أدابتر بينفّذ نفس الدوال: `getLessons`، `getSheikhs`، `getSeries`، `getOverrides`، `saveOverrides`، `uploadAudio`، `audioUrl`. الصفحات والداشبورد بيكلموا الواجهة بس، ومش عارفين التخزين فين.
- **السرعة مش بتتأثر:** حتى مع قاعدة بيانات، الصفحات العامة بتتبني جاهزة. التعديل من الداشبورد بيحدّث الصفحات اللي اتأثرت بس، في ثواني (On-demand Revalidation)، من غير ما يبني الموقع كله.
- **أدوات Python تفضل تطلّع JSON.** فيه أمر واحد (`pnpm data:sync`) بيدخّل البيانات في أي أدابتر اختاره المسجد. كده أدوات Python مش محتاجة تعرف حاجة عن قواعد البيانات.
- **أسرار الاتصال** (روابط قواعد البيانات ومفاتيحها) بتتحط في إعدادات Vercel بس، عمرها ما تتكتب في الملفات.
- **أي حد يقدر يضيف أدابتر جديد:** ملف واحد بينفّذ الواجهة، واختبارات جاهزة بتتأكد إنه شغال صح. وده باب كويس لمساهمات المجتمع.
- **ننقل من أدابتر لأدابتر** بأمر واحد (export / import)، فمفيش مسجد بيتحبس في اختيار.

## 9. لغات كتير (الأردو والهندي والروسي وغيرهم)

**الموقع هيتبني من الأول على إنه متعدد اللغات.** ده رخيص وإحنا بنبدأ، ومكلف جدًا لو اتضاف بعدين.

**طبقتين:**
1. **لغة الموقع نفسه** (الزراير والقوايم: «استمع»، «الدروس»، «خطب الجمعة»…): ملف ترجمة لكل لغة، `messages/ar.json` و`ur.json` و`hi.json` و`ru.json`… بمكتبة **next-intl**.
2. **لغة المحتوى** (عناوين الدروس): بتفضل باللغة اللي المسجد بيكتب بيها في القناة. مسجد في لاهور هيكتب أردو، ومسجد في قازان هيكتب روسي.

**الإعدادات:**
```json
"i18n": { "default": "ur", "locales": ["ur", "en"] }
```
- مسجد بلغة واحدة: الموقع كله بيها ومن غير ما الرابط يتغير.
- مسجد بأكتر من لغة: زرار لتغيير اللغة، والرابط بيبقى `/ur/…` و`/en/…`.

**اللغات في الإصدار الأول:** العربي، الإنجليزي، الأردو (باكستان)، الهندي، الروسي. **وبعدها بسهولة:** الإندونيسي، التركي، البنغالي، الفرنساوي، الملايو، السواحيلي… كل لغة = ملف ترجمة واحد.

**التفاصيل اللي بتفرق:**
- **الاتجاه:** العربي والأردو من اليمين للشمال، والهندي والروسي والإنجليزي من الشمال لليمين. التصميم كله هيتكتب بخصائص منطقية (`start`/`end` مش `left`/`right`)، فيقلب لوحده.
- **الخطوط حسب الكتابة:** الأردو محتاج خط نستعليق (Noto Nastaliq Urdu)، والهندي محتاج Devanagari، والروسي محتاج خط فيه سيريلي. قايمة الخطوط في الإعدادات بتتفلتر حسب اللغة.
- **التاريخ الهجري** وأسماء الشهور بكل لغة (Intl بيدعم ده)، والأرقام بشكل كل بلد.
- **أسماء السور** بكل لغة، والبحث بيلاقي السورة بأي اسم.
- **البحث** بيتعامل مع كل لغة صح: الهمزات والتشكيل في العربي والأردو، والحروف الكبيرة والصغيرة في الروسي.
- **أدوات Python:** الكلمات اللي بتعرّف الشيخ (زي «الشيخ»، «مولانا»، «Шейх») وأنواع المقاطع بتبقى في الإعدادات حسب اللغة، مش مكتوبة جوه الكود.
- **الداشبورد** بلغة المسجد كمان.
- **الدليل وAGENTS.md** بيتترجموا، والـ AI بيكلم كل واحد بلغته.

**الترجمة نفسها:** الـ AI بيعمل أول نسخة، و**لازم مسلم من أهل كل لغة يراجعها** قبل ما نعلّمها «جاهزة». ولحد ما تتراجع، بتظهر «تجريبية» في قايمة اللغات. وهنفتح باب لأي حد يساهم في الترجمة (بـ Pull Request، أو بعدين بـ Crowdin).

## 10. المراحل: هتشوف إيه في آخر كل واحدة

كل مرحلة بتتعمل على **فرع منفصل** في mosque-media، وبيبقى ليها **لينك تجربة على Vercel**. مفيش أي حاجة بتتدمج في الأساسي غير بموافقتك.

### المرحلة 0: الأساس (جلسة واحدة)
- تسطيب Node.js وpnpm على جهازك (بإذنك)
- مشروع Next.js فيه: قراءة الإعدادات بـ zod، الألوان، الخط، الوضع الليلي، الهيدر واللوجو
- **هيكل اللغات من أول يوم:** next-intl، العربي (يمين لشمال) والإنجليزي (شمال ليمين)، وكل كلمة في الموقع من ملف ترجمة
- **واجهة البيانات (§8)** وأول أدابتر: `github-json`
- **هتشوف:** لينك تجربة فيه هيدر الموقع بألوان المسجد التجريبي، والوضع الليلي، وزرار يقلب بين العربي والإنجليزي والصفحة تقلب اتجاهها.

### المرحلة 1: الصفحات العامة (2–3 جلسات)
- كل صفحات القايمة اللي في §4 (من غير المشغّل الكامل)، والبحث، والفلاتر، وتطبيق overrides، والـ SEO، باللغتين
- **هتشوف:** الموقع التجريبي كامل تتصفحه بالعربي والإنجليزي، وجدول المقارنة متعلّم فيه اللي خلص.

### المرحلة 2: المشغّل والتطبيق (1–2 جلسة)
- المشغّل بكل مميزاته، والتحميل، والمشاركة، والـ PWA، والشغل من غير نت
- **هتشوف:** تسمع درس، تتنقل بين الصفحات والصوت شغال، تثبّته على موبايلك.

### المرحلة 3: الداشبورد (2 جلسة)
- `/lawha` بـ shadcn، والدخول الآمن، والحفظ عن طريق واجهة البيانات، والرفع عن طريق Vercel Blob (§5)
- **هتشوف:** تدخل الداشبورد على لينك التجربة وتعدّل مقطع وتشوفه اتغير.

### المرحلة 4: لغات أكتر (1–2 جلسة)
- الأردو والهندي والروسي: ملفات الترجمة، والخطوط (نستعليق وDevanagari وسيريلي)، والتاريخ الهجري، وأسماء السور، والبحث بكل لغة، وكلمات أدوات Python
- مسجد تجريبي بالأردو وواحد بالروسي على لينكات تجربة
- **هتشوف:** نفس الموقع بالأردو (يمين لشمال بخط نستعليق) وبالروسي (شمال ليمين). والترجمات تفضل «تجريبية» لحد ما حد من أهل كل لغة يراجعها.

### المرحلة 5: أدابترات بيانات أكتر (1–2 جلسة)
- `supabase` و`postgres` للبيانات، و`s3`/R2 و`vercel-blob` للصوت، وأمر `pnpm data:sync`، والنقل بين الأدابترات
- اختبارات موحدة كل أدابتر لازم يعدّيها
- **هتشوف:** نفس الموقع التجريبي شغال مرة على JSON ومرة على Supabase، من غير أي فرق للزائر.

### المرحلة 6: التشطيب
- اختبارات Playwright لكل بند في §4 وبكل لغة، وفحص السرعة (§6)، والوصول (قارئ الشاشة والكيبورد)، وتحديث README وAGENTS.md والأدلة
- **هتشوف:** تقرير فيه نتيجة كل اختبار وأرقام السرعة جنب الموقع الحالي.

### المرحلة 7: إطلاق mosque-media v2
- النسخة الحالية تتحفظ باسم `v1` (اللي عايزها يلاقيها)، والجديدة تبقى الأساسية
- **محتاج موافقتك قبل الرفع.**

### المرحلة 8: نقل موقع الحسني (بعد ما v2 تثبت)
- موقع الحسني يتبني على v2 كأول مسجد، **بهويته هو** (ألوانه، خطوطه، القبة، الأغلفة) في طبقة شكل خاصة بيه، **مش بتتنشر في mosque-media**
- يفضل على `github-json` و`github-releases` زي دلوقتي (مجاني ومجرّب)
- يشتغل على **لينك تجربة جنب الموقع الحقيقي** أسبوع، ونقارن صفحة بصفحة
- بعد موافقتك نحوّل الدومين. **ولو حصلت أي مشكلة، Vercel بيرجّع النسخة القديمة بضغطة واحدة.**

### بعد كده: الأدوات
تقطيع الصوت، ثم التفريغ النصي (البحث جوه كلام الدرس نفسه، وبكل لغة)، واحدة واحدة، وكل واحدة بخطة صغيرة لوحدها.
